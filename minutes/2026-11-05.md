    - Conformance document conformance model for publishing WSG by 4/30/27 - Tzviya, Hidde

      - Tim: I found our discussion on this at TPAC helpful. We have the idea of continuous improvement, that’s good.

      - Hidde: One common thread is around measurability, enforceability and comparability. Look for things that can be used by someone in power (sustainability dept / regulator / government) as a way to set rules - what are things that people can include as requirements? There was a suggestion by Jeroen by roles so that each is counted separately and then get an aggregated score.

      - Tim: We have sectional scoring. How is this different?

      - Alex: We have sectional conformity with threshold levels (e.g. I meet UX, I meet WebDev etc). The model already allows for ag scoring. What is measurable is a tricky question because we don’t know - unclear what can/cannot be measured at this point. We ask for evidence, and the people looking at the evidence can decide if meet criteria.

      - Hidde: How is it different from current? Suggestion is to have multiple documents, e.g. procurement needs to meet X, Data centers meet X. Organizations hate to be partially compliant. Reaching full compliance is an accomplishment. Re measurability: many of the current criteria leave too much up to the person meeting the criteria, so it’s impossible to compare. Regulators need to be able to treat everyone the same.

      - Jen: We’re still early in tech for measurements objectively and subjectively. Equity MM includes Sustainability. I recommend a Maturity Model. A draft MM would help with adoption to show a pathway.

      - Tzviya: we need to look at audience… that is the ‘user’… people trying to make their websites/practices more sustainable, not necessarily regulators. When we think about the conformance model we need to look at audience, is that the user? How much objectivity do we need? We could consider separating conformance model too (and potentially improve in next charter).

      - Alex: the model as it currently stands is as unbiased as possible. We currently don’t have a way to make it more objective. Status quo is probably best we can come up with given our constraints. Not saying we can’t improve, we absolutely can, eg if we have more ability to test. That will help us come up with a framework for like, what’s machine testable, and this is how to do it etc. Given current frameworks this is particularly hard. Asking evidence is probably best we can do right now, with SCI for web and other developments we’ll be able to make it better in the future.

      - Hidde: agree with what Alex says, it may be easier to do this better later. Wanted to ensure to also mention that apart from the regulatory aspect, there is the procurement aspect: I want to be able to tell me colleague who is buying software to purchase a sustainable product rather than non-sustainable.
